CAT OPERATOR SIMULATION MODULE
Frontend-Only UI & Simulation Experience Blueprint
React + Framer Motion • Minimal Hackathon Interface • 23 September 2026
1. Purpose
This document contains only the frontend requirements for the operator simulation module. It defines what the operator sees, the screen flow, UI components, frontend state, interactions, animations and the visual behavior of the simulation. Backend, ML training, dataset generation and API implementation details are intentionally excluded.
2. Dataset Context Used by the Frontend
The frontend must remain compatible with the project datasets already decided: a 1,000,000-row large dataset and a 150,000-row compact dataset using the same finalized feature schema. The UI does not expose every dataset column as a control. Instead, it presents only the parameters relevant to the selected task and machine.

3. Basic Frontend Diagram
The complete frontend experience should follow this simple flow:
[ TASK SELECT ]       ↓[ MACHINE SELECT ]       ↓[ PARAMETER SETUP ]       ↓[ MACHINE SIMULATION ]       ↓[ RESULT + FEEDBACK ]       ↺    TRY AGAIN
Inside the simulation screen, the main interaction is: operator changes parameters → starts run → machine state/progress changes → estimated completion time updates → result is shown → operator retries.

16. Retry Loop
The frontend should make retrying effortless:
RESULT → TRY AGAIN → CONFIGURATION → RUN → SIMULATION → RESULT
When Try Again is selected, preserve the previous parameter values and allow the operator to modify only what they want. This makes the learning loop visible.

23. Final Frontend Experience
The frontend should feel like a lightweight digital machine console with a training-game loop. The operator chooses a task, chooses a machine, adjusts a manageable set of controls, starts the simulation, watches the machine state change, receives an estimated completion result, understands what affected the result, and retries. The UI should make this loop obvious within seconds.
